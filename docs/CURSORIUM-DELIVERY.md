# CURSORIUM v1.0 工程交付

日期：2026-10-13（Europe/Budapest）。优先顺序按功能、扩展性、稳定性/性能、视觉细化实施。

## 变更总结

保留原 C#/.NET 8/WPF/Win32 技术栈、原始 FROST 的全部 CUR/ANI/PNG/SVG 资源、采样与穿透覆盖层、托盘、启动项和安装器机制。原 FROST 资源重新生成后与 Git 基线无内容差异；新增 `theme.json` 清单及完整的 Obsidian 深色套装。

新增 ThemeCatalog、CursorTheme、EffectCatalog、StudioService、ProfileManager、ClickEffectManager 和本地 LivePreview。主题管理继续使用原注册表/SPI 路径，扩展为可逐次回滚和重启恢复的事务。四种拖尾共用渲染引擎；点击效果独立于拖尾。三栏 UI 从统一目录生成选项与卡片，主按钮与控制项均连接真实服务。

配置明确区分草稿、已应用和已保存 Profile；保存与应用均使用独立副本，避免界面预览污染桌面状态。已应用 JSON 的写入失败会同时回滚 Windows 指针。原始备份不会被下一次主题切换替换。

修正原生句柄所有权：验证通过 `LoadImage` 获取可释放句柄，共享系统句柄不销毁；自定义 WPF 指针先从控件移除再释放。关闭/暂停不再保持持续绘制。预览区域避开已应用桌面覆盖层，保持草稿反馈清楚。

## 安全回退与数据保护

基线提交 `6efcd1b` 已建立本地回退分支 `codex/rollback-frost-v1`；开发在 `codex/cursorium-v1`。开始时工作区干净，无用户未提交修改。

系统测试使用单独数据目录，结束恢复测试前的 Windows 指针状态。原用户 `original-theme.json`、`settings.json`、`studio.json` 和 `profiles.json` 通过测试前后存在性/SHA256 校验；原备份没有被测试归档或替换。实测只针对测试进程，不删除现有安装或原资产。

原始日志、测试截图、重新启动探针和性能测量位于 `artifacts/cursorium-verification/`。可分享的脱敏汇总位于 `docs/verification/`。架构与文件格式见 [架构文档](CURSORIUM-ARCHITECTURE.md)。

## 未解决和未验证项目

- 本次硬件为 Windows 11 build 26100、一个 2560×1440 显示器、96 DPI。Windows 10、多屏混合 DPI、负坐标屏幕布局、物理热插拔和睡眠/恢复尚未实机覆盖。覆盖层逻辑继承原多屏实现；旧版历史验证不算本版本通过。
- 已检查 960×640、960×600 和 850×520 DIP 的 WPF 布局与关键控件。真实 125%/150%/200% DPI 切换尚未验证，不能用紧凑窗口替代硬件验证。
- 安全桌面、保护/提权窗口、游戏独占全屏未进行实际测试。已验证外部无边框全屏窗口自动暂停；其他环境依赖保守桌面检查和手动暂停。
- 已构建新安装器，但为保护现有安装和活动备份，没有在本机重跑新版本安装/卸载或升级安装往返。便携版的真实运行已验证。安装器测试脚本保留相应环境检查。
- 性能是短时稳态采样，绘制数是 WPF invalidate 次数，不能宣称 GPU 展示 FPS。长期泄漏、长时间高负载及真实 120 Hz 展示尚未证明。
- 原系统配置里为空的角色没有独立资源时，系统项预览使用当前共享系统指针；恢复的注册表值仍以备份为准。
- 导入器目前为按角色导入资源，不支持任意压缩主题包。库显示内置/已导入主题，不枚举全部外部 Windows 命名方案。无签名 Windows x64 包，UI 仅完成简约实用布局。
